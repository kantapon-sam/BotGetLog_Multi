BotGetLog_Multi v1.2.20

ZTE Link Optical exports now take Max BW from the physical interface's reported
BW instead of the SFP module label. A port reporting BW 10 Gbit/s with a
6G-10km-SFP module exports 10G. Interface state is reset at every interface
header so subinterfaces and smartgroups cannot overwrite a physical port's BW.
Older logs without interface BW retain the optical-label fallback.

The Linux server update patches Check_Link_Optical.class and the version
manifest in the installed BotGetLog_TrueCorp.jar and Link_Optical.jar. Other
archive entries, libraries, scheduler scripts, inventory, credentials, daily
budgets and retained logs stay unchanged. No new collection is needed to
re-export existing completed logs. Keep previous JARs for rollback.

Validation uses the exact candidate JARs: six regression suites per JAR cover
ZTE bandwidth, Nokia state/neighbor/metrics, free ports and CPU/memory exports.
The retained CCS8515 log exports xgei-1/1/0/26 to PN-CCS0013-1 port 2/1/12 as
10G through both parser and complete single-file export paths.

Windows distribution and portable packages include the same bandwidth fix.
The v1.2.19 updater installs and relaunches v1.2.20 while preserving inventory,
credentials, custom workbook sheets, logs, preferences and encrypted enable
settings. Package contents retain the verified v1.2.19 libraries and portable
Java runtime. Every unrelated JAR entry remains byte-for-byte unchanged.

GitHub Release assets and their SHA-256 checksums are verified before the
Windows Auto Update manifest is advanced. TrueLogs receives its own immutable
Bot runtime through the validated runtime publisher, without restarting the
web service or changing the runtime pinned to existing jobs.

Configured Ant builds now invoke publish-true-web-runtime after all dist
artifacts are ready. release.ps1 -SkipBuild invokes the same publisher for
prepared packages. Publication errors fail the configured build/release.
Machine-specific publisher paths and credentials remain in ignored settings.
